# Conformance suite

Every LIN implementation must pass these cases. The Rust, TypeScript, Python and WebAssembly test
suites all run them.

| Directory | Each case | Requirement |
| --- | --- | --- |
| `write/` | `name.json`, `name.lin`, `name.split.json`, `name.split.lin` | Writing `name.json` with the default options gives `name.lin` byte for byte (with `split` on, `name.split.lin`), and both read back to `name.json`. The `.json` files are also the canonical JSON layout every implementation writes |
| `read/` | `name.lin`, `name.json` | Hand-written LIN, valid but not in the writer's layout, reads as `name.json` |
| `invalid/` | `name.lin` | Every reader rejects it |
| `schema/` | `typed.lin`, `typed.json` (and split) | Read with the schema in `schemas/`, the LIN gives the JSON; written with it, the JSON gives the LIN (split form with a split limit of 5) |
| `schemas/` | `<hash>.lin`, `<hash>.json` | The schema for `schema/`; its data hashes to its name |

The files are generated by `generate.py` from the Python implementation; after changing a rule,
regenerate them and review the diff.
